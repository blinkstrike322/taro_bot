# Дизайн: «Оккультный терминал 2.0» — редизайн UX таро-бота

Дата: 2026-10-04
Статус: утверждён в диалоге, ожидает ревью спеки
Область: web-морда (Telegram Mini App) + контент-слой (расклады, проводники). Backend-LLM, платежи, резерв квоты, Telegram-слой — не трогаем.

---

## 1. Цель

Сохранить уникальную терминальную идентичность ARCANUM, но убрать «дерганность» и «плоскость»: плавные анимации, читаемая подача чтения, интересный каталог раскладов, характерные проводники. Целевой эффект — «хочется остаться в боте после расклада».

## 2. Диагноз (что сломано и почему)

### Анимации
- `web/src/components/shell/ProseType.tsx` — React-ререндер на каждый символ (`setN(i)` каждые ~8–12мс) → ~100 ререндеров/сек при одновременно работающих тяжелых ambient-слоях (`AmbientSigil` ~6.8k SVG-узлов, `CrtNoise` canvas, blur-дым) → дропы кадров, текст «печатается блоками».
- `Math.random()*4` джиттер на self-scheduling `setTimeout` → при залипании кадра typing замирает и прыгает.
- `web/src/components/ReadingResult.tsx` — задержки секций pre-computed из `proseDuration()`, реальный typing дрейфует → секции наезжают/висят.
- Повсеместные `steps(N)` easing'и → «рваность».
- `web/src/hooks/useSpread.ts` — хардкод `setTimeout(950ms)` после флипа без loading-состояния → мертвая пауза, если LLM не успел.
- Автоскролл `behavior:'smooth'` на каждый тик (`Shell.tsx`).

### Подача чтения
- Для 3+ карт `buildBodyGroups` возвращает `visible: []` → разбор позиций и связь карт спрятаны в свёрнутые `<details>`. Видны только серые (`grayscale(1) contrast(1.5)`) миниатюры + строка «signal». Это корень «расклады пососные».
- Типографика: body 13px, метки 10.5px, `▊` блочный курсор, всё JetBrains Mono → чтение выглядит как вывод программы.
- `[ DAILY TRANSMISSION ]`, `exit 0`, `//` — машинная рамка вместо ритуальной.

### Расклады
- Каталог = 3 строки (`TuiMenu.tsx`), позиции генерятся keyword-matching'ом (`core/prompts.py:_positions_for_question`). Нет именованных раскладов, count захардкожен (`app.py`: `count = 3 if ... == "3" else 1`).

### Проводники
- 3 гайда по 8 exemplars в `voice_pool`, узкий diction → выходят «безхарактерными».

### UI-мусор (по скриншотам Playwright-тура)
- Пентаграмма-фон коллизирует с правой колонкой контента на каждом экране.
- Мобильные 2-колонки рвутся (help, описания команд); гайды обрезаны `…`; dead space в help/motd; слабые tap-афордансы; mirrored «THE HIEROPHANT» читается как баг; card-frame клипается титлбаром; чип-бар 3+3+2 ряда.

## 3. Что не меняем

- Идентичность: терминал, JetBrains Mono как база, `●/○`, ANSI-теги, boot-секвенция, светящаяся логотипка, дизеринг карт.
- Backend: цепочка LLM-провайдеров, voice_gate, схема БД, резерв квоты (атомарный SQL), платежи (Stars), aiogram-слой, напоминания.
- Telegram Mini App как среда (Next.js static export в `static/webapp`).

## 4. Область 1 — Движок анимаций

### 4.1 Новый typing-движок (замена ProseType/Typewriter)
- Один rAF-цикл на активный typing. Текст инжектится в DOM-текстовую ноду напрямую (ref), батчами N-символов за кадр по delta-time (скорость задается в символах/сек). React-state — только `typing | done`.
- Базовая скорость ~60–80 симв/сек с микро-вариацией (±10%) по плавной функции (sin-шум), не по random-per-char.
- Пунктуационные паузы сохраняются (`.!?…` +120мс, `,;:—` +50мс) как пауза в rAF-потоке.
- Курсор: тонкий `│` в `--guide-accent`, blink через opacity (не steps по ширине).
- `prefers-reduced-motion` → мгновенный показ (уже есть флаг instant — переиспользовать).

### 4.2 Event-driven секвенция чтения
- Секции чтения строятся в цепочку: старт следующей — по `onDone` предыдущей. `proseDuration()` и pre-computed `--jl-delay` для prose-секций упраздняются; не-prose строки (метки, артефакты) получают фиксированные малые stagger-задержки внутри своей секции (25–35мс).
- Скелет: `<ReadingResult>` получает `sections[]` из интерпретации, рендерит их последовательно.

### 4.3 Гашение ambient-слоев при typing
- `Shell` вешает класс `is-typing` на root на время активного typing. CSS: у `AmbientSigil`, `CrtNoise`, smoke-градиентов, constellation/lunar — `animation-play-state: paused` + opacity ↓ (~50%). После печати — плавный возврат (transition 1.2s).

### 4.4 Readiness вместо хардкода
- После флипа последней карты: если whisper готов → ритуальная пауза 700–900мс → печать. Если нет → видимое состояние «канал отвечает…» (существующий `PendingLine`), переход по резолву промиса + минимум 600мс, чтобы моргнуло.

### 4.5 Сглаживание CSS
- Все декоративные `steps(N)` → `cubic-bezier(.3,.7,.2,1)`-семейство. `steps()` остается только для: blink курсора, braille-спиннер.
- Автоскролл: rAF-throttle; отключается, если юзер скроллит вручную (флаг по touch/wheel), возобновляется по новой записи.

## 5. Область 2 — Подача чтения

- Разбор позиций — **инлайн** для всех раскладов: блок на позицию = метка позиции (моно caps 12px, accent, tracking) → имя карты (Cormorant Garamond 600, 22–26px, кириллица) → ориентация (перевёрнутая/прямая) → проза 15px/1.65. «Связь карт»/синтез — отдельный инлайн-блок перед советом. В `<details>` остаются только опциональные вещи (траектория дня в daily).
- Миниатюры карт в чтении: **цветные**, без grayscale; для 3+ карт — горизонтальный ряд с номерами позиций.
- Заголовок чтения: `✦ <ИМЯ РАСКЛАДА> ✦` (accent); метa-строка сохраняется, но без `//`-стайла внутри чтения. `exit 0` → рандомизированные ритуальные подписи per-guide (см. Область 4, closing lines).
- Шрифты: добавить Cormorant Garamond (500/600, кириллица) только для имен карт и заголовка чтения. Остальное — JetBrains Mono.
- Совет: рамка-свиток (тонкая рамка + уголки-глифы), 14–15px.
- Отступы: секции чтения разнесены (24–32px), метки секций не меньше 12px.

## 6. Область 3 — Система раскладов

### 6.1 `data/spreads.json` — источник правды

Схема записи:
```json
{
  "id": "pentagram",
  "name": "Пентаграмма",
  "aliases": ["пента", "pent"],
  "cmd": "taro pentagram",
  "count": 6,
  "mode": "pentagram",
  "layout": "pentagram",
  "needs_question": true,
  "flip_order": ["earth","air","water","fire","spirit","center"],
  "positions": [
    {"key":"center","name":"Сигнификатор","desc":"Суть ситуации; кто ты в ней. Вскрывается последней."},
    {"key":"spirit","name":"Дух","desc":"Квинтэссенция; сквозная линия, объединяющая всё. Не предсказание."},
    {"key":"fire","name":"Огонь","desc":"Воля, импульс, что рвётся вперёд."},
    {"key":"water","name":"Вода","desc":"Чувства, интуиция, невысказанное."},
    {"key":"earth","name":"Земля","desc":"Тело, деньги, дом, опора."},
    {"key":"air","name":"Воздух","desc":"Мысль, слово, ясность; истории, которые мы себе рассказываем."}
  ],
  "synthesis": "Какой элемент доминирует, какой голодает, какие два в диалоге. Дух — не предсказание.",
  "quota_cost": 1
}
```

### 6.2 Каталог (8 раскладов)

| id | Имя | Карты | Layout | Позиции |
|---|---|---|---|---|
| `daily` | Карта дня | 1 | column1 | энергия дня (существующий) |
| `single` | Одна карта | 1 | column1 | прямой ответ на вопрос (существующий) |
| `yesno` | Да/Нет | 3 | trio-inline | за · против · совет; short_answer содержит вердикт: да / скорее да / скорее нет / нет |
| `three` | Три карты | 3 | pyramid | динамические позиции из `_positions_for_question` (существующий) |
| `mfd` | Мысли·Чувства·Действия | 3 | trio-inline | мысли · чувства · действия (о другом человеке) |
| `shadow` | Тень | 6 | spine | 1 что я скрываю · 2 почему скрываю · 3 что скрывание защищает · 4 что оно стоит · 5 путь интеграции · 6 следующий шаг (одно действие на неделю) |
| `pentagram` | Пентаграмма | 6 | pentagram | см. схему выше; флип: земля→воздух→вода→огонь→дух→центр |
| `horseshoe` | Подкова | 7 | arc | 1 ситуация · 2 скрытые факторы · 3 препятствие · 4 внешнее влияние · 5 твоя позиция · 6 позиция других · 7 исход при текущей линии |

Квота: все расклады `quota_cost: 1` (зафиксировано; пересмотр — отдельно).

### 6.3 Backend-изменения
- `spread_type` → строковый id из spreads.json (обратно совместимо: `daily`|`1`|`3` маппятся на старые).
- `count` берется из spread-данных (убрать хардкод в `app.py`).
- `core/prompts.py`: `_spread_mode()` разрешает id из spreads.json; `build_reading_prompt` собирает позиционный блок из `positions` + `synthesis` + спец-инструкции mode (`yesno` → требование вердикта; `pentagram` → порядок чтения элементов и запрет трактовать Дух как событие; `shadow` → спуск без эзотерического пафоса, конец — конкретный шаг).
- Резерв квоты: `reserve_reading(count=1)` без изменений.

### 6.4 Frontend-изменения
- `commands.ts`: команды-алиасы: `taro mfd|чувства`, `taro yesno|данет`, `taro shadow|тень`, `taro pentagram|пента`, `taro horseshoe|подкова`. `taro ask` остается свободным вопросом → `three`.
- `SpreadBlock` рендерит по `layout`: `column1` (есть), `pyramid` (есть, выровнять — убрать random OFFSETS), `trio-inline` (ряд 3), `spine` (колонка 4 + 2 справа), `pentagram` (5 вершин звезды + центр), `arc` (дуга 7). Флип в порядке `flip_order`.
- `TuiMenu` catalog — из spreads.json (заглушка-каталог в мок-API обновляется синхронно).

## 7. Область 4 — Проводники (углубить 3 существующих)

В `data/characters.json`, по каждому гайду:
- `voice_pool`: 8 → 14–16 exemplars (шире интонации: тепло/строгость/игра/тишина).
- `diction.imagery`: 10–14 слов, `diction.anti` пополнить.
- `rhythm`: конкретика (длина фраз, частота коротких предложений, паузы-тире).
- Характерные фишки (в persona): Странница — полушёпот, обращение «малыш»; Хранитель — нумерует истины, метафоры руин/камня; Искра — прозвища, разговорное «слушай, ну смотри».
- `whispers`: расширить пул (реплики при раздаче/флипе).
- **Новое поле `closings[]`**: 5–8 финальных фраз после чтения (Странница — укрывает; Хранитель — ставит точку; Искра — подкалывает с теплом). Рендерится в конце чтения вместо `exit 0`.
- `greetings`, `daily_voice`, `field_voice` — освежить под новые расклады (минимум 1 пример про тень/пентаграмму).
- temperature без изменений (0.85 / 0.55 / 1.0).

## 8. Область 5 — Полировка UI

1. Sigil-collision: `.menu-box`/фреймы чтения — фон `rgba(5,4,15,.85)` + `backdrop-filter: blur(6px)`; `AmbientSigil` opacity ↓ и позиция выше/левее контентной зоны.
2. Мобильные 2-колонки → стек (командный список MOTD, help, меню-описания).
3. Гайды: описание без `…`, 2 строки.
4. Dead space: help/motd получают ритуальный футер (`# тени слушают · <random>`).
5. Меню: чеврон `▸` на каждой строке, активная строка — заметный tint + accent-бордер слева.
6. Чип-бар: компактная группировка в 2 ряда (приоритет: daily / ask / catalog).
7. Mirrored card title: убрать зеркалирование; card-frame — margin-top от титлбара.
8. Статуслайн: показывает контекст режима (название расклада, номер флипа).

## 11. Ограничения и риски

- Telegram WebView (слабые Android) — главный таргет перфа; движение: DOM-инжект вместо ререндеров + пауза ambient-слоев.
- Обратная совместимость API: `/api/spread/begin` получает spread_type строкой — старые клиенты (`?type=1|3|daily`) должны продолжать работать.
- Курсорные фичи (LunarGlyphs, Constellation) не удаляем — только производительность.
- Не расширять scope на бэкенд-LLM/платежи.

## 12. Верификация (Definition of Done)

1. Playwright-тур повторно: скриншоты всех экранов/фаз каждого нового расклада на мок-API; сравнение «до/после».
2. Jank-замер (PerformanceObserver longtask) до/после: цель — 0 long tasks > 50ms во время typing.
3. Юнит-тест: каждый spread в spreads.json имеет mode/positions/flip_order; `build_reading_prompt` успешно строит промпт для каждого mode; старые типы `1|3|daily` маппятся.
4. e2e на мок-API: полный флоу каждого из 8 раскладов (команда → раздача → флипы в flip_order → чтение с инлайн-позициями).
5. Ручная проверка контраста: минимальный кегль на мобиле ≥ 12px, dim-текст ≥ rgba(255,255,255,.45).
