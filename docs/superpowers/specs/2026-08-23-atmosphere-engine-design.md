# Taro Bot — Next Level Redesign: «Атмосферный движок»

**Дата:** 2026-08-23
**Статус:** утверждено пользователем (все секции)
**Подход:** A — Атмосферный движок (единый слой атмосферы, вау-моменты как его состояния)

---

## 1. Цели и рамки

Довести проект до next-level по двум осям:

- **Арт**: три вау-момента (вход-ритуал, раскрытие карты, экран толкования), облака в интерфейсе (гибрид: живописная основа + пиксель-дизер кромка), цветок х2 с более изящной геометрией и осознанной композицией, редизайн плашки толкования и типографики.
- **Техника**: стабильное качество LLM-ответов на бесплатных моделях (сейчас «плавает»), полная сенсорная идентичность проводниц (сейчас влияние ограничено акцентным цветом).

**Ограничения:**
- Только бесплатные LLM (Zen / OpenRouter free). Платные модели — вне скоупа.
- Платформа: Telegram WebView (iOS/Android). Бюджет: +<15KB JS gzip, +<250KB ассетов.
- Все анимации — `transform`/`opacity` только. `prefers-reduced-motion` отключает атмосферу.
- UI обязан работать при отказе любого подслоя атмосферы и при полном фейле LLM.

**Вне скоупа:** память проводниц о прошлых сессиях (идентичность + память — отдельный будущий проект), новые проводницы, новые типы раскладов, бэкенд-инфраструктура деплоя.

## 2. Архитектура: Атмосферный движок

### 2.1 Состав

- **`AtmosphereProvider`** — React context: `{ guide, phase, moonPhase, reduceMotion }`.
- **`AtmosphereLayer`** — fixed-слой, z-позиция между `.app-bg` и контентом.

**Входы:**
- `guide: GuideMeta` — текущая проводница.
- `phase: 'welcome' | 'draw' | 'reveal' | 'reading'` — `reveal` эмитится спред-компонентами в момент переворота карты; `reading` — при получении толкования.
- `moonPhase: number (0..1)` — детерминированный расчёт из даты, кэш на день.
- `reduceMotion: boolean` — из `matchMedia('(prefers-reduced-motion: reduce)')`.

### 2.2 Подслои (сзади вперёд)

1. **`CloudField`** — гибридные облака:
   - 2 банка мягких живописных PNG (~90KB каждый, WebP где возможно), тонировка проводницы через CSS filter + mix-blend;
   - пиксель-дизер кромка поверх (процедурный SVG-паттерн-маска) — переход облака в фон;
   - медленный параллакс-дрейф, только CSS-анимации.
2. **`GlowLayer` + `MotesLayer`** — существующие слои из `globals.css` (`.glow-layer`, `.light-motes`), прокачиваются: свечение подхватывает акцент проводницы.
3. **`FlowerAnchor`** — ирис х2 (см. секция 3), позиция анимируется CSS-переходами между фазами.

### 2.3 Вау-моменты как состояния движка

| Фаза | Поведение атмосферы |
|---|---|
| `welcome` | Облака сходятся из центра к краям; boot-ритуал в голосе проводницы; цветок прорастает снизу |
| `draw` | Облака в рабочем дрейфе; цветок крупный слева-снизу (spread-экран) |
| `reveal` | По перевороту карты: облака расступаются (расход по X + провал opacity), вспышка света акцентом проводницы (расширение существующего `burst-flash`), цветок усиливает покачивание на 1 цикл |
| `reading` | Построчное проявление текста толкования (staggered fade+blur); цветок перетекает на поля справа, уменьшенный |

Смена проводницы → кроссфейд всей атмосферы 600мс.

### 2.4 Отказоустойчивость

Каждый подслой — независимый компонент с собственным error-boundary: падение одного не роняет остальные и UI. Без ассетов облаков → статичный градиент (текущий `.app-bg`).

## 3. Цветок х2 (`PixelFlower` v2)

- **Разрешение:** `STEP=2 → STEP=1` → 100×164 живых ячеек (×4 плотность), штрихи 0.5px.
- **Изящество:**
  - дуговые филаменты-тычинки (новый орган, 2 шт.);
  - полутоновые переходы дизером к краям лепестков (эффект растровой печати, как на референсе-постере);
  - стебель — тонкая линия с точечной фактурой вместо сплошной колонны; более выразительный изгиб;
  - 2 бутона-спирали у основания.
- **Композиция:** перестаёт быть случайным обрезком. Spread-экран: крупный ≈70vmin, якорь левый-низ с «дыханием» от края. Reading: уменьшенный на полях справа (замена текущего декора в `ReadingResult`).
- **Per-guide:** свой `seed` + `tilt` + цвет. Селена — стройный; Веста — приземистее, крупный фол; Лилит — рваные кончики лепестков.
- **Рендер:** ~3–4k SVG-ячеек, `useMemo` по seed, статичны кроме групп покачивания (механизм `flower-sway` сохраняется).

## 4. Плашка толкования + типографика (`ReadingResult` v2)

Из «редакционных линий» → **манифест-плашка** (язык сохраняется, добавляется иерархия):

- **Шапка:** ряд сигилов проводницы + двойной тонкий рулерт; tech-label `толкование · {имя} · {настроение дня}`.
- **Интро:** Cormorant italic 25px, `accentDeep`, висячая кавычка.
- **Основной ответ (`short_answer`):** Manrope 16px / line-height 1.8; буквица первой строки пиксельным шрифтом в цвет акцента (высотой ~2 строки).
- **Карты говорят (`card_meaning`):** пиксель-ординалы `01 / 02 / 03` + тонкие линейки (вместо точек-буллетов).
- **Совет (`advice`):** serif 20px на маргиналии, дизер-подчёркивание.
- **Фон:** `paper-bright` + noise + мягкая заливка `accentSoft` у верхней кромки + существующие `pixel-brackets`.
- **Проявление:** построчный staggered fade+blur («фото в проявителе»); плашка выезжает из-под перевёрнутой карты.

## 5. Проводницы: полная сенсорная идентичность

### 5.1 Фронт — расширение `GuideMeta` (`web/src/lib/guides.ts`)

```ts
clouds: {
  bank: 'moon' | 'ember' | 'storm',  // выбор PNG-банка
  drift: number,                     // скорость дрейфа
  tint: string,                      // CSS filter
  density: number,                   // облаков в кадре
};
flower: { seed: number; tilt: number };
revealBurst: { symbol: string; count: number };
welcomeScript: string[];             // boot-лог в голосе проводницы
```

**Профили:**
- **Селена** (`moon`): высокие тонкие облака, медленный дрейф, холодный серебристо-синий; луна-компаньон на входе; boot «вода в чаше».
- **Веста** (`ember`): низкие тёплые облака-дым, янтарное свечение снизу; медленно; boot «растопка очага».
- **Лилит** (`storm`): рваные штормовые клочья, быстрый дёрганый дрейф; розово-вишнёвые искры; boot «поджиг фитиль».

### 5.2 Бэк — `characters.json` + `core/prompts.py`

1. **`voice_examples`** — 2 мини-примера (вопрос → intro + advice) в голосе проводницы; инжект в system prompt как few-shot. Главный рычаг стабильности голоса на бесплатных моделях.
2. **Настроение дня** (детерминированный seed от даты + проводницы, вместо random на каждый расклад):
   - Селена — фаза луны;
   - Веста — время суток (утро → «янтарный полдень», вечер → «вечерний дым» и т.д.);
   - Лилит — hash дня.
   - Настроение стабильно весь день и **показывается в UI** («сегодня у неё гроза») — характер становится видимым.
3. Настроение дня прокидывается в ответ API → tech-label шапки плашки.

## 6. LLM: качество на бесплатных моделях (`core/llm.py`)

**Корень проблемы:** хедж «первый успешный ответ побеждает» — быстрые слабые модели (laguna/mimo/deepseek-flash) крадут расклад у качественных (nemotron-3-ultra, score 99).

**Решение — validation gate + retry:**

1. **Validation gate** после парсинга JSON:
   - `short_answer` ≥ 200 символов;
   - нет forbidden-фраз (персонных + `GLOBAL_FORBIDDEN`);
   - имена выпавших карт присутствуют в тексте;
   - эмодзи: по-прежнему вырезаются из ответа (`strip_emojis`), но их наличие в сыром ответе = маркер слабой модели → ответ не проходит gate, идёт retry.
2. **Провал gate → следующий хедж-заход** с другой моделью (до 3 попыток суммарно, таймауты без изменений).
3. **`response_format: {"type": "json_object"}`** для поддерживающих моделей — меньше битого JSON.
4. **Кулдаун после 2 подряд неудач** (сейчас одной достаточно — один таймаут выкидывает nemotron на 5 минут).
5. **Temperature 0.8 → 0.75** + few-shot из секции 5.
6. Порядок моделей остаётся data-driven (`scripts/benchmark_models.py`).

**Латентность:** gate добавляет до +15с в худшем случае (редко — обычно первый ответ валиден); средняя латентность не меняется.

**Фолбэк:** `fallback_from_cards_db` остаётся, тексты освежаются под голоса проводниц.

## 7. Перфоманс, ошибки, тестирование

**Перфоманс:**
- Только `transform`/`opacity`-анимации (компоузер).
- PNG-банки облаков ≤ 2 × ~90KB.
- `FlowerAnchor`: SVG memoized, пересчёт только при смене seed.
- `prefers-reduced-motion` → атмосфера статична (расширение существующего блока в `globals.css`).
- Проверка: iPhone SE-класс, бюджетный Android, Telegram WebView.

**Отказоустойчивость:**
- Подслои Atmosphere независимы (error-boundary на каждый).
- Оффлайн/медленная сеть → спред работает, атмосфера деградирует до статичного градиента.

**Тесты:**
- pytest: validation gate (валидный / битый JSON / короткий / с эмодзи / без имён карт); cooldown после 2 неудач; mood-of-the-day детерминизм.
- PixelFlower: sanity-тест генератора (число ячеек в диапазоне, детерминизм от seed).
- Ручной визуальный QA трёх вау-моментов на устройстве.
- `scripts/e2e_check.py` — прогон полного цикла расклада.

**Деплой:** пересборка Next.js export → `static/webapp` (существующий процесс, `amvera.yaml` не меняется).

## 8. Порядок реализации (набросок для планирования)

1. LLM-пайплайн (gate, cooldown, response_format, few-shot, mood-of-the-day) — независим от фронта.
2. PixelFlower v2 (х2, изящество, per-guide).
3. AtmosphereLayer + CloudField (ассеты банков, дизер-кромка, фазы).
4. Вау-моменты: welcome-ритуал, reveal-оркестрация, ReadingResult v2 с проявлением.
5. Перф-проход + тесты + визуальный QA.

Каждый шаг — отдельно верифицируемый; фронт-шаги 2–4 зависят друг от друга частично (3 ← 2, 4 ← 3), шаг 1 полностью параллелен.
