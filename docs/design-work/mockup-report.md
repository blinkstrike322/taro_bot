Через Codex in-app browser, без подмены скрытого состояния приложения:

- Все восемь раскладов от каталога до общего чтения: 1/1/3/3/3/6/6/7карт. На экранах синтеза сломанных изображений нет (`screenshots/flow-checks.json`).
- Главная → вопрос → стол → выбранная карта → чтение; обратный переход сохраняет открытые карты.
- Пентаграмма на320px: документ и экран не имеют горизонтального переполнения; подписи/геометрия проверены визуально. Главная, стол и Луна на390px сохранены.
- Три акцента выбираются через четвёртую вкладку. Перезагрузка сохраняет выбранную Искру Хаоса (`aria-pressed=true`).
- Открытие старой Подковы из журнала и добавление подготовленного уточнения. После reload сохранены вопрос и исходный Хранитель Руин, хотя текущая настройка — Искра Хаоса.
- JS-синтаксис проверен `node --check`, `git diff --check` прошёл.

При проверке исправлены гонка быстрых касаний во время View Transition, неработающие пути вложенных файлов в visual companion, сброс позиции чтения при restore, лишняя ширина ряда семи карт и возможность менять вопрос внутри уже созданного сеанса. Теперь «Новый вопрос» создаёт новый сеанс, старый остаётся в журнале.

## Пределы этой проверки

- Нет настоящего Python API, модели, квот или Telegram в макете. Все тексты подготовлены; это явно указано на доске вне мобильной композиции. Полная локальная студия запланирована в спецификации, ещё не реализована.
- В прототипе 7подготовленных карт и один новый стилевой этюд; весь производственный deck78 не переработан. Перевёрнутые карты и все78URL будут проверяться в приложении.
- Поведение на настоящих Telegram iOS/Android, клавиатура, full accessibility audit и длительное чтение не проверялись. Reduced-motion CSS есть, отдельный визуальный прогон этой настройки в данном макете не выполнялся.
- Готовность макета пройти сценарии не является художественной приёмкой. Оценка владельца запрошена после показа макета/спецификации, до переноса.

## Запуск

Без visual companion: `python3 -m http.server 3212 --bind 127.0.0.1 --directory docs/design-work`, затем `/ritual-v3.html`. Это статический макет с собственным localStorage key, он не обращается к API. Для companion ассеты копируются плоским списком в его content directory: его `/files/` маршрутизатор использует basename и не читает вложенные директории. Session keys/служебные файлы companion находятся только в игнорируемой `.superpowers/` и не коммитятся.

## Следующее действие

Получить оценку конкретного дизайна, затем составить проверяемый план и исполнять через `subagent-driven-development`. Не выдавать макет за исправленный полноценный localhost и не менять приложение до этого шага Superpowers, если владелец явно не отменит согласование.
